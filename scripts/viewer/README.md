# Самодостаточный просмотрщик модели — один HTML-файл

Собирает страницу, которая открывается двойным кликом, работает без интернета
и без локального сервера. Внутрь вшиты модель, three.js и декодер Draco.

## Сборка

```
# 1. библиотеки в один классический скрипт (entry.js кладём в корень проекта,
#    иначе esbuild не найдёт node_modules)
cp scripts/viewer/entry.js _viewer_entry.js
node node_modules/.bin/esbuild _viewer_entry.js --bundle --format=iife --minify \
     --outfile=scripts/viewer/libs.js
rm _viewer_entry.js

# 2. сшиваем всё в один файл
python scripts/viewer/build_single.py <модель.glb> <итог.html> public/draco
```

## Почему именно так

* **Никаких ES-модулей.** Из `file://` браузер блокирует и модули, и `fetch`
  локальных файлов, поэтому three.js и загрузчики собираются в один классический
  скрипт через esbuild, а модель кладётся в страницу как base64.
* **Декодер Draco подменяется.** `DRACOLoader` штатно скачивает
  `draco_wasm_wrapper.js` и `draco_decoder.wasm` по сети — из файла это не
  сработает. В `viewer.js` переопределён `_loadLibrary`, он отдаёт вшитые данные.
* **Draco, а не квантование.** Квантование не требует декодера, но даёт 16 МБ
  против 11 МБ у Draco. С учётом вшитого декодера (0,32 МБ) Draco всё равно
  заметно выгоднее.
* **base64 раздувает на треть.** Модель 11,21 МБ превращается в 14,94 МБ текста,
  итоговый файл — около 16 МБ. После загрузки строка обнуляется,
  чтобы не держать её в памяти.

## Что внутри просмотрщика

Два режима: осмотр снаружи (орбита) и прогулка внутри от первого лица с
коллизиями через three-mesh-bvh. Точка входа и высота глаз те же, что на сайте.
Сайтовой обвязки нет — ни меню, ни текстов, ни форм.
